## 2026-08-07

- **Git "dubious ownership" on /workspace: fixed with `safe.directory` in `entrypoint.sh`.**

  Bind-mounted files arrive carrying the macOS host uid (501); the container runs as
  appuser (1000). Git compares repo st_uid against geteuid() and refuses every command.
  Writes were never blocked — enforcement is host-side — so git's heuristic was the only
  real breakage.

  Rejected alternatives (both were floated as "cleaner", neither works here):
  - *Remap ownership at the Colima mount.* No such knob exists. Colima's sshfs, virtiofs,
    and 9p mounts all present the host uid.
  - *Run the container as uid 501.* The entrypoint needs root for `init-firewall.sh`
    (NET_ADMIN/iptables) before it `gosu`s to appuser.
  - *`usermod -u 501 appuser` at startup.* Would need `chown -R /home/appuser` over the
    asdf/node/npm/claude trees on every start, and risks the docker group membership and
    the claude install-method bookkeeping the Dockerfile deliberately sets up.

  Implementation notes: **both** `/workspace` and `/workspace/*` entries are required —
  the wildcard covers nested repos (submodules, worktrees) but not the mount root itself
  (verified on git 2.47.3). `--unset-all` runs first so the list can't accumulate
  duplicates if `~/.gitconfig` is ever made to persist across runs the way `~/.claude` is.

- **OpenWolf pinned to 1.0.4 (`ARG OPENWOLF_VERSION`), deliberately off `latest`.**

  The 2.x line — 2.0.1 was current and is what bare `npm install -g openwolf` was pulling
  in — has bugs we hit in practice, so the image holds at the last 1.x release. Previously
  this was the only unpinned component in the image, so every rebuild could silently move
  it; node/python are pinned via ARG and Claude Code via `DISABLE_UPDATES`.

  1.0.4 and 2.0.1 declare the same `engines` (`node >=20`, image runs 24.18.0) and the same
  bin path (`dist/bin/openwolf.js`), so the asdf shim resolution is unaffected by the
  downgrade. Revisit once 2.x is known good.
