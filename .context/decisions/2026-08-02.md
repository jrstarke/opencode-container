## 2026-08-02
- ~/.claude in the container is a named Docker volume (`opencode-sandbox-claude-config`), not a host bind mount. It only seeds from the image the first time it's created, so anything baked into the image under ~/.claude (CLAUDE.md, plugins, settings.json) silently stops updating on rebuilds once the volume exists. Fix: kept the volume (a single-file bind mount for just `.credentials.json` risks breaking OAuth token refresh, which writes via temp-file-then-rename), but `entrypoint.sh` now allowlists `.credentials.json` on every start — wipes everything else under ~/.claude and re-seeds CLAUDE.md/settings.json/plugins from an image-owned `/opt/sandbox-seed/`.
- Found along the way: `~/.claude/projects/-workspace/` (memory + session/resume history) was shared across every different host project ever run through this sandbox, since they all bind-mount to the same `/workspace` path and Claude Code keys project state by that path. Confirmed by finding an unrelated project's memory entries in this container's state. Now wiped on every start along with the rest of the non-auth state.
- `claude plugin install` writes `enabledPlugins` into settings.json, so settings.json is baked to the real `~/.claude/settings.json` path *before* the plugin install step (not written straight to the seed dir) and copied to the seed dir *after* install, so the seed captures the merged result. Getting this order wrong would make the plugin install successfully but silently never load.
- Verified all of the above against a cloned copy of the live volume (never the volume this session itself runs from) plus a fresh empty volume, not just via `docker build`.
